01What the Product Directory does

One place for every product your vendors send — and a robot that puts each one on the right Shopify websites, at the right price, in the right words.

Every product a vendor sends lands in Products. From there the app works on its own, every minute: it reads the photos and the vendor's text, decides which of your Shopify websites the product belongs on, works out the selling price for each website, writes a title, description and Google (SEO) text in that website's own style, adds that website's tags, and puts the product on the store.

How one product travels

  1. Lands — a product comes in. It comes straight from the vendor's Telegram channel (see Connect Telegram), or you add it in Products → + Add product. Status: New.
  2. Read — the AI looks at the photos and the vendor's post and fills in name, category, fabric, colour, sizes, cost price and other details (work, occasion, wash care…). Status: Reading, then Ready — or Needs info when the cost price or the category is missing.
  3. Sorted — each website's Routing rules decide whether the product goes there. Every "yes" becomes a *listing*: one product on one website.
  4. Priced and written — for each listing the price is worked out from the cost with that website's formula, and that website's AI writer writes the title, description, SEO text, tags and photo descriptions.
  5. Published — the listing is sent to Shopify: live, as a draft, or held until someone approves it — whatever that website's Publishing mode says.
Tip One product can be on several websites, each with its own price, title, description and tags. Changing one website never changes another.

Where things are

Who can do what

  • Admins, managers and operators can use every page: add and edit products, approve, publish, change website settings.
  • Only an admin or manager can save a store's credentials (the Shopify keys), the Telegram bot token and the crawler key.

02Before you start: categories, the AI reader and vendors

Ten minutes, once. Everything after this depends on it.

Categories

  1. Open Settings → Categories & tags.
  2. Under Categories, type each category you sell and tap Add — for example Saree, Kurta Set, Lehenga, Dupatta, Co-ord Set.
  3. Tap a category to choose the attributes it needs (Colour, Work…) — see Tags: your own lists.

The AI must pick one of these for every product. A product without a category — or without a value for one of its category's attributes — waits in Needs info. Routing rules, tags and the Shopify product type all use the category, so spell each one exactly the way you want it to appear on your websites.

The AI that reads products

  1. In Settings → AI that reads products, pick a Model and an Effort. Haiku 5.5 with Model default is enough for reading.
  2. Tap Save reader.

This AI only reads (fills in the facts). Each website chooses its own writer later, under Websites → Content & AI.

Vendors

  1. Open Vendors → + Add vendor.
  2. Name: the vendor as you know them, e.g. Rangoli Creations.
  3. Short code (optional): two or three letters, e.g. RG. Tags can use it as {vendor_code}.
  4. Tap Save vendor. Repeat for each vendor.
Tip Stopped buying from someone? Tap Deactivate instead of deleting. Their old products stay; they just stop showing up as a choice for new ones.

03Step 1 — Add and connect each Shopify store

Do this once for every website. You need the store's myshopify.com address and a Shopify login that is allowed to install apps (the store owner, or staff with that permission).

Add the website

  1. Open Websites → + Add website.
  2. Name: how you call it, e.g. Indya Ethnic.
  3. Store domain: the myshopify.com address, e.g. indya-ethnic.myshopify.com — find it in Shopify admin → Settings → Domains. Not your own .in / .com domain.
  4. Tap Add website. The website opens on its Connection tab.

A new website starts Off with the routing set to Do not list it, so nothing is sent until you have finished setting it up.

Which way to connect?

Your situationWhat you useIn the app pick
The store already has an older custom app made inside the Shopify admin, with an Admin API access token that starts shpat_That app's access tokenAccess token
Anything else — a new store, or no such appA new app from the Shopify Dev DashboardClient ID + secret
Note Shopify stopped letting anyone create new "legacy" custom apps in the store admin on 1 January 2026. Old ones keep working. Every new connection is made in the Shopify Dev Dashboard (Way B).

Way A — an existing custom app (token starting shpat_)

  1. In the Shopify admin open Settings → Apps and sales channels → Develop apps, and open the app.
  2. Check its Admin API scopes include write_products, read_products, write_publications, read_publications — plus write_inventory if this website will track stock. If you add any, save and reinstall the app when Shopify asks.
  3. Copy the Admin API access token (it starts with shpat_). Shopify shows it only once — if nobody saved it, use Way B instead.
  4. In the app: Websites → your website → Connection. Under How the app signs in pick Access token, paste it into Admin API access token, tap Save credentials.

Way B — a new app from the Shopify Dev Dashboard

  1. Sign in to the Shopify Dev Dashboard (dev.shopify.com) with a Shopify account in the same organisation as the store. An app from another organisation cannot connect to the store.
  2. Create an app, e.g. DailyOffice Product Directory.
  3. In the app's access settings add the scopes write_products, read_products, write_publications, read_publications — plus write_inventory if this website will track stock. Release that version.
  4. Install the app on the store and approve it.
  5. Open the app's settings and copy the Client ID and the Client secret.
  6. In the app: Websites → your website → Connection. Under How the app signs in pick Client ID + secret, paste both, tap Save credentials.
Tip Shopify renames its screens now and then. If a label above looks different, follow the same idea: create app → give permissions (scopes) → release → install on the store → copy client ID and secret.

Test, then switch on

  1. Tap Test connection.
  2. Green Connected to <store name>. All needed permissions are there. — done.
  3. Yellow Missing permissions: … — add those scopes to the app in Shopify, reinstall / approve it, then Test connection again.
  4. Red Last problem: … — the details are wrong or the app was removed. Copy them again, Save credentials, test again.
  5. Finish Steps 2 to 6 below for this website. Then come back to Connection and switch Active on.
  • Active can only be switched on after a successful connection. Switching it on also sends the Ready products already in the directory that match this website's rules. Off = nothing new is sent to this store; products already there stay.
  • Credentials are kept on the server only and are never shown again — the boxes stay empty. Leave them empty to keep what is saved; type only to replace.
  • With Client ID + secret the app renews its Shopify access by itself. Nothing to do.
  • Moving a website to a different Shopify store: change Store domain, enter that store's credentials and tap Save credentials. The website is switched off, the old store's keys are deleted, and its products are queued to be sent again to the new store. Products already on the old store stay there.

04Step 2 — Decide which products go to this website

Websites → your website → Routing rules.

When no rule matches

ChoiceWhat it means
Do not list it (safe default)Nothing goes to this store unless a rule sends it. Recommended.
List everythingEvery product goes to this store unless a rule keeps it off.

This choice is saved with Save changes at the bottom of the screen. Rules save on their own.

Add a rule

  1. Tap + Add rule.
  2. Rule name — for you, e.g. Silk sarees from Rangoli or Nothing under ₹500.
  3. When a product matches — Send it to this store or Keep it off this store.
  4. Fill only the conditions you need. Every condition you fill must match; empty ones are ignored: Vendors, Categories, Fabrics (any of these, capital letters do not matter), Cost from ₹ / Cost up to ₹ (the vendor cost), Keywords (any of these words in the name, SKU, details or what the AI read).
  5. Optional, for "Send" rules: switch on Own price for these products and set a Markup % and Add ₹ that replace the website's own for these products.
  6. Tap Save rule.

Order matters

Rules are checked from the top. The first switched-on rule that matches decides, and the rules below it are not looked at. Use the ↑ ↓ buttons to change the order. Put "Keep it off" rules above wide "Send" rules.

#RuleShown as
1Nothing under ₹300KEEP OFF · cost ₹0–₹300
2Bridal lehengasSEND · Lehenga · words: bridal · own price: +150% + ₹200
3Silk sarees from RangoliSEND · vendor Rangoli · Saree · fabric Silk

With "When no rule matches" set to Do not list it: a ₹250 silk saree from Rangoli is stopped by rule 1. A ₹1,800 silk saree from Rangoli is sent by rule 3. A cotton kurta matches no rule, so it is not listed.

  • A rule with no conditions matches every product (the app warns you).
  • The switch on a rule turns it off without deleting it.
  • A change applies to products that arrive or are checked again after it. For the products already in the directory, tap Send matching products now under the rules (or open one product and tap Check websites again).
  • Deleting a rule never removes products that are already listed.

05Step 3 — Set the selling price

Websites → your website → Pricing. The price in the vendor's post is your COST; each website turns it into its own selling price.

Selling price = cost × (1 + Markup % ÷ 100) + Add ₹, then rounded, and never below the minimum price.

BoxWhat to type
Markup %100 doubles the cost, 80 adds 80%.
Add ₹ (after markup)A fixed amount on top — shipping, packing, payment charges.
RoundingHow the final number looks (table below).
Compare-at % (was price)0 = no struck-out price. 30 = show a "was" price 30% higher.
Minimum price ₹Never sell below this. Empty = no minimum.

Worked example: cost ₹640, Markup 80%, Add ₹60

640 × 1.8 = 1,152, plus 60 = ₹1,212 before rounding.

RoundingHow it works₹1,212 becomes
No roundingKept as it is (to the paisa)₹1,212
Nearest 10To the nearest ten₹1,210
Ends in 99Up to the next …99. A price already ending in 99 stays (₹1,299 stays; ₹1,300 → ₹1,399)₹1,299
Ends in 49 / 99Up to the next …49 or …99₹1,249

Compare-at (the struck-out "was" price)

With Ends in 99 and Compare-at % 30: 1,299 × 1.3 = 1,688.70, rounded the same way → shoppers see ₹1,699 struck out next to ₹1,299.

Minimum price

Cost ₹250: 250 × 1.8 + 60 = 510 → Ends in 99 → ₹599. With Minimum price ₹ 799 the website sells it at ₹799. The minimum is applied after rounding, so choose a "nice" number like 799 or 999.

A rule's own price

The "Bridal lehengas" rule above uses +150% + ₹200. Cost ₹6,000: 6,000 × 2.5 + 200 = 15,200 → Ends in 99 → ₹15,299. Rounding, compare-at and the minimum still come from the Pricing tab.

Tip Use the Preview box: type a Sample cost ₹ to see the price, the struck-out price and your margin before you tap Save changes.

New pricing applies to listings written from now on. A listing already on Shopify keeps its price until its product is checked again: open the product and tap Check websites again — the new price goes to Shopify and the text stays. A price typed by hand (kept) never changes on its own.

06Step 4 — Tags in this website's structure

Websites → your website → Tags. Each store filters and builds collections from tags in its own way — one may use "Fabric_Silk", another plain "silk". This tab sets the pattern for this store.

  • Tag templates — each line becomes one tag. Type it and press Enter. Words in curly brackets are filled from the product.
  • Fixed tags — added to every product sent to this store, e.g. New Arrival.
  • How {tags} is written — Plain sends the value as it is (Maroon); Prefixed puts the attribute in front (Colour_Maroon, or the attribute's own Shopify prefix from the Tags page).
  • Letter case — As written, lowercase or Title Case.
  • AI extra tags — switch on to let the AI add style / occasion tags it sees in the photos and text, up to At most tags. Fill Only from these tags and it picks from that list and adds nothing else.
  • How many tags — At most, per product caps the final list (8 on a new website), after the templates, fixed tags and AI extras.
PlaceholderFilled withExample
{tags}The product's chosen values (see Tags: your own lists), one tag each, plain or prefixed — new websites start with itMaroon, Zari — or Colour_Maroon
{category}The categorySaree
{fabric}The fabricBanarasi Silk
{color}The colourMaroon
{vendor}Vendor nameRangoli
{vendor_code}Vendor short codeRG
{size}One tag per sizeSize_S, Size_M, Size_L
{sku}Product codeRG-101
{attr:occasion}Any detail the AI read — work, occasion, pattern, set_contents, wash_care…Festive
{attr:store_tags}The other store's tags, raw (Import from website) — usually {tags} is what you wantIdeal Collection

Example

Templates {category}, Fabric_{fabric}, Color_{color}, Size_{size}, Vendor_{vendor_code}, Occasion_{attr:occasion} and the fixed tag New Arrival, for a maroon Banarasi silk saree from Rangoli (RG), Free Size, festive, give:

Saree Fabric_Banarasi Silk Color_Maroon Size_Free Size Vendor_RG Occasion_Festive New Arrival

  • If a placeholder is empty for a product, that tag is skipped — you never get a half tag like "Fabric_".
  • Commas inside a tag become spaces (Shopify splits tags at commas). Repeats are removed, whatever the capital letters.
  • The Example box at the bottom of the tab shows the tags for a sample product as you type.
  • Shopify's product type is set to the category automatically.

07Step 5 — Titles, descriptions and SEO

Websites → your website → Content & AI. For every listing the AI writes the title, description, SEO title, SEO description, web address (handle), two questions and answers, extra tags and photo descriptions — for this website alone (see Store profile).

Model and effort

ModelGood forCost
Haiku 5.5Fast; good for most listingsLowest
Sonnet 5.5Better writing — your main storeAbout 20 × Haiku
Opus 5.5The best writing — a premium storeHighest

Effort (Model default, Low, Medium, High, Extra high, Max) is how hard the model thinks before writing. Higher is slower and costs more. Model default suits most listings; models that do not support effort ignore it.

Tip Start every website on Haiku 5.5 with Model default. Read 10–20 listings. Move a website up to Sonnet only if its writing is not good enough.

The other settings

SettingWhat it does
LanguageEnglish, Hinglish, Hindi…
Brand voiceHow this store talks, e.g. "premium, elegant, festive — for brides and wedding guests".
Image alt textOn: the AI describes each photo for Google and for screen readers.
Title pattern{ai_title} lets the AI write the title. Or build it: {color} {fabric} {category} → "Maroon Banarasi Silk Saree". Also usable: {vendor}, {sku}, {name}; mix them, e.g. {ai_title} {sku}.
Title style for the AIHow the AI should build its title, in your words, e.g. "Colour, fabric, type, then the work". The search phrase from the store profile is always in it.
Length limitsTitle (characters), Description (words) (200 on a new website: the AI writes about two thirds of it or more), SEO title (characters) (Google shows about 60), SEO description (characters) (about 155).
Extra instructionsAnything to always do or avoid, e.g. "Mention free shipping above ₹1,999. Never use the word cheap."
Note The AI is told to use only the facts given and never to invent a fabric or size. Still, read the first listings of every new website before you set it to Live.

Plain, natural wording

The writer describes a product the way someone who knows it would tell a shopper: plain facts, no sales pitch. It is told to leave out the usual AI habits, such as slogans ("Elegance redefined."), "not just a kurta, it's a statement", praise words like *stunning* or *exquisite*, benefits nobody stated ("ensuring all-day comfort") and long dashes. When there is little to say about a product it writes less instead of padding. The rules follow the Humanizer writing guide.

Tip Brand voice and Extra instructions still have the last word. If a store should sound more festive or more like an advert, say so there.

Descriptions use only simple formatting (paragraphs, bullet points, small headings, bold, italics, line breaks), so they look right on any Shopify theme. Save the tab with Save changes.

08Step 6 — Publishing mode, the Active switch and pausing

Websites → your website → Publishing.

Publishing modeWhat happensUse it when
LivePublished and visible on the store straight awayYou trust this website's setup
DraftSent to Shopify as a draft — someone makes it visible inside ShopifyYou want a last look inside Shopify
Review firstWaits in Products as Needs review until someone taps Approve, then publishesA new website, the first weeks

Track stock — on: Shopify counts stock and stops selling at 0 (the app needs write_inventory). New products start at 0, so they cannot be bought until you set their quantities in Shopify. Off: always orderable — right for made-to-order or vendor-held stock.

Three ways to stop things

SwitchWhereWhat it does
Active (one website)Websites → website → ConnectionOff = nothing new is sent to this store. Products already there stay. On again = the matching products are sent.
Rule switch (one rule)Websites → website → Routing rulesThat rule stops sorting products.
Automation (everything)Settings → AutomationPaused = nothing is read, written or published on its own. Buttons like Publish now still work. The Dashboard shows a yellow banner.

Settings → Run now does one round straight away (it can take up to 2 minutes) and shows how many products were read, routed, written, published and failed.

A safe first day for a new website

  1. Set Publishing mode to Review first and tap Save changes.
  2. On Connection, switch Active on.
  3. Add three or four real products in Products.
  4. Open each one, open this website's listing, read it, fix anything, tap Approve.
  5. Check the products on the store. Happy? Switch Publishing mode to Live.

09Store profile — one voice per store

Websites → your website → Store profile. Fill it once for each store. The AI reads it before every listing, so two stores get a different title, description, SEO text, questions and photo descriptions for the same product. The facts (fabric, colour, work, sizes) stay the same everywhere.

SettingWhat it does
Brand nameEvery SEO title ends with it, e.g. "… | Kreeva". Empty uses the website's name.
MarketWhere the shoppers are (India, USA, UK…). The writer uses the words they search with.
Spelling and MeasurementsBritish / Indian (colour, jewellery) or American (color, jewelry); Inches or Centimetres.
AudienceWho shops here, in a line.
AngleWhat this store leads with. The description opens with it. Give each store a different one.
Search phraseThe phrase each listing is written for, built from the product: {color} {fabric} {category} gives "Maroon Georgette Kurta Set". Also usable: {work}, {occasion}, {name}.
Questions in the descriptionOn: the two questions and answers sit at the end of the description, so every theme shows them.
Custom fieldsOn: fabric, work, colour, occasion, what is in the set and the questions also go to Shopify as custom fields (custom.fabric, custom.faq…) for themes and filters that read them. Other apps' fields are never touched.
Ordering detailsDelivery time, Stitching and Returns. The writer puts them in an "Ordering from …" part of the description, in its own words. Leave all three empty and that part is left out.

What every listing gets

  • A title with the search phrase in it once.
  • A web address of 3 to 6 plain words, with no design codes.
  • An SEO title that ends with the brand name, and an SEO description of about 140 to 155 characters.
  • A description: an opening in the store's angle, 5 to 7 fact bullets, "How to wear it", and "Ordering from …" when you gave ordering details.
  • Two questions and answers a shopper would really ask, answered only from the facts and your profile.
  • A different description for each photo (alt text), and tags from your own lists.

Checked before it goes out

After the AI writes a listing, a program checks it. If something is wrong the AI rewrites it once. If it is still wrong, the listing waits in Needs review with the reason, even on a Live website, and you decide.

The checkWhat it catches
Copied wordingFive or more words in a row taken from the supplier's text or from another store's version. Facts such as "Kurta, Pant and Dupatta" may repeat.
Same as another storeThe same title, SEO title or opening line as the listing on another store.
Search phraseMissing from the title, from the first 50 words or from the SEO title.
Names and claimsThe supplier's name, a design code, a link or phone number; "No. 1", "only 3 left", invented reviews.
Ordering detailsA number of days that is not in your store profile.

Open the listing to see the reason and the smaller notes ("Also worth a look"). You can fix the text by hand, tap Regenerate, or Approve it as it is. The editor also shows the Search phrase (change it, save, then Regenerate) and the two Questions.

Note Nothing is written for a product until its necessary details are there: cost price, category, fabric, colour, at least one photo and its required tags. Until then it stays in Needs info and says what is missing.

What the AI cost

Each website's listing shows AI cost in rupees. The product page adds everything up for that product: reading it, choosing tags and writing for every website, rewrites included. The Dashboard shows the total for the month. Dollars are turned into rupees at ₹95.

Tip The first store written for a product has nothing to differ from. Each later store is told what the earlier ones say and must open differently, so the order does not matter to you.

10Connect Telegram — vendor posts become products by themselves

Do this once (about an hour). After it, every product a vendor posts in their Telegram channel is in Products the next morning, with the vendor already filled in — taken from the channel, because the post itself never names the vendor.

How it works

  1. A crawler — one of your staff Telegram accounts, running on a small cloud server — looks at each vendor channel once a day, overnight, each channel at its own time.
  2. It forwards that channel's new posts into your private admin group, one channel at a time, so the group is never flooded.
  3. The Playbook bot is an admin in that group. It passes every forwarded message to Playbook.
  4. Playbook joins the photos, videos and text of one post into one product and sets the vendor from the channel. Then the usual steps run: read by the AI, sorted, priced, written, published.

You need: your own Telegram account (to make the bot), a staff Telegram account for the crawler (a normal account with a phone number, not a bot — bots cannot read other people's channels), a laptop for one sign-in, a GitHub account that can see kreeva-lifestyle/unsort (an owner of that organisation approves Railway's access), and a card for Railway's Hobby plan (about US$5 a month).

1 · Create the bot in @BotFather

  1. In Telegram search for @BotFather (blue tick) and open it.
  2. Send /newbot. Give it a name, e.g. DailyOffice Playbook, then a username that ends in bot, e.g. dailyoffice_playbook_bot.
  3. BotFather sends a token — numbers, a colon, then letters, e.g. 123456789:AAH…. Tap it to copy it. Keep it private.
Tip Come back to @BotFather after step 3 (once the bot is in your group): send /setjoingroups, pick your bot and choose Disable. Then nobody can add the bot to other groups.

2 · Save the token in Playbook

  1. In Playbook open Settings → Telegram. Under 1 · Playbook bot, paste the token into Bot token and tap Save token.
  2. You see the bot's @name and Connected. If it says Telegram can’t reach Playbook, tap Check bot; if it stays red, tap Change token and save the same token again.
  • Only an admin or manager can save the token. Everyone else sees the status.
  • The token is kept on the server and never shown again.

3 · Add the bot to your admin group and link it

  1. In Telegram make a private group, e.g. Vendor posts, with you and the staff account (step 4). Keep it just for this.
  2. Open the group, tap its name → Edit (pencil) → Chat history for new members → Visible → save. This turns it into a supergroup, the only kind Playbook can use. If you skip it, the bot tells you so when you send the link code.
  3. Open the group, tap its name → Add members → add your bot. Then tap Edit (pencil) → Administrators → Add Admin → pick the bot → tap ✓ to save. The bot must be an admin to see the forwarded posts.
  4. In Playbook, under 2 · Admin group, tap Get link code. A 6-digit code appears, valid for 30 minutes.
  5. In the group send /link 123456 (your code instead of 123456) — or tap Copy /link … in Playbook and paste it.
  6. The bot answers Linked to Playbook ✓, and Settings shows Linked with the group's name within a few seconds.
  7. Now go back to @BotFather → /setjoingroups → your bot → Disable (see the tip in step 1).
Tip Messages people type in the group are ignored; only forwarded vendor posts become products. 5 wrong codes and the code stops working — tap New code.

4 · The staff account: its keys, and join every vendor channel

  1. On a laptop open my.telegram.org and sign in with the staff account's phone number (the code arrives in that account's Telegram app).
  2. Open API development tools. Create an app — any name, e.g. Playbook crawler, platform Other.
  3. Copy the api_id (a number) and the api_hash (letters and numbers). You need both in step 6.
  4. From the staff account, join every vendor channel you want to read, and make sure it is a member of the admin group and can send messages there.
Tip In the staff account: Settings → Privacy and Security → Groups & Channels → My Contacts, so strangers cannot pull it into their groups.

5 · Create the crawler key

  1. In Playbook, under 3 · Crawler, tap Create crawler key (admins and managers only).
  2. Tap Copy key and paste it into Railway (step 6). It is shown only once — when it is saved, tap I saved it — hide.
Tip Best done when Railway's Variables page is open (step 6), so you paste the key straight in. Lost it? Tap Replace crawler key — nothing uses it until the crawler runs.

Replace crawler key makes a new key and stops the old one at once — paste the new one into PB_CRAWLER_KEY on Railway straight away.

6 · Start the crawler on Railway

First make TG_SESSION — the staff account's sign-in for the crawler. Do this once, on a laptop:

  1. Install Node.js from nodejs.org — the big LTS button (the one for most users) — and click through the installer.
  2. Download the crawler: on GitHub (signed in) open kreeva-lifestyle/unsort → green Code button → Download ZIP, and unzip it.
  3. Open the folder unsort-main/tools/pb-telegram-crawler in a terminal. Windows: right-click the folder → Open in Terminal. Mac: open Terminal, type cd (with a space), drag the folder into the window, press Enter.
  4. Type npm install and press Enter. Wait until it finishes. Windows: if it says *running scripts is disabled*, type npm.cmd install instead (and npm.cmd run login below).
  5. Type npm run login and press Enter. Type the api_id, the api_hash, the staff phone number with +91, then the code Telegram sends in the app, and the two-step password if the account has one. Nothing shows while you paste the api_hash or type the password — that is normal.
  6. It prints TG_SESSION once — a long line of letters. Copy it for the Variables below.
Note TG_SESSION is a login. Anyone who has it can read and send messages as the staff account. Paste it only into Railway's Variables — never into a chat, email or WhatsApp. To cancel it: Telegram on the staff phone → Settings → Devices → end that session, then run npm run login again.

Then put the crawler on Railway:

  1. Open railway.com → Sign up with GitHub → choose the Hobby plan and add a card.
  2. New Project → Deploy from GitHub repo. When Railway asks, allow it to see the kreeva-lifestyle organisation, repository unsort — then pick unsort.

How the times are picked: channels are checked once a day inside the window, 11:00 PM to 7:00 AM unless you change it. The first channel gets the middle of the window (3:00 AM).   • Settings → Telegram → 3 · Crawler → Daily checks lists every channel in time order: vendor, time, Next check and the last result.
  • Edit window (admins and managers) changes the start and end — at least 1 hour; it may run past midnight. Saving spreads every channel evenly over the new window.
  • Spread evenly (admins and managers) gives every channel a new time, evenly spaced, in the same order. Use it after adding or removing many vendors. Nothing is copied twice. Best done in the daytime: done at night, a channel whose new time has already passed is checked the next night.
  • A vendor added in the daytime is first checked at its time that night. Clearing the channel, or Deactivate on the vendor, stops its checks.
  • A post from a channel that no vendor has yet still comes in (if someone forwards it): Playbook makes a new vendor named after the channel. When a vendor reposts another channel's post, it still goes to the vendor whose channel it came from.

11Import products from a website

Paste another store's web address and Playbook copies its in-stock products into Products. From there the usual steps run: the AI reads each one, the website rules decide where it goes, and the listing is written and published.

How to do it

  1. Open Products. On a computer tap Import from website next to + Add product; on a phone tap the Import from website row at the top of the list.
  2. Type or paste the store's address (for example example.com) and tap Check website. Playbook looks at the store for a few seconds. The whole store is imported, even if you paste the address of one collection.
  3. Read the preview: what kind of store it is, about how many products it has, three sample products with their prices, and anything to know (in the yellow box).
  4. Vendor name is filled in from the store's name — change it if you like. Every imported product gets this vendor.
  5. Leave Only in-stock products on unless you also want sold-out items.
  6. Leave Sell at their price on to use the store's price as our selling price (see below).
  7. Tap Import about 980 products (the number is the estimate; it reads Import up to … when the store cannot say how many are in stock). A tile at the top of Products shows the progress; you can leave the page, it keeps going on the server.

What Playbook can read

Kind of storeWhat you seeWhat is copied
Shopify storeGreen dotEvery product: name, description, photos (up to 10), sizes, colour, price, whether it is in stock
WooCommerce storeGreen dotThe same, from the store's own product list
Other store — best effortYellow dotOnly the pages that carry product data, found through the site map. Some products may be missed, and it is slower (about 25 pages a minute)
Unknown storeRed boxNothing was found — check the address or try the store's home page

"In stock" means the store itself says the product (any of its sizes) can be bought right now. A product whose every size is sold out is left out while Only in-stock products is on.

The details it copies

Besides the name, description, photos, sizes and price, Playbook keeps every detail the other store shows about a product. They appear on the product page in the From the website tile (text only — they are never sent back to that store), and the AI reader leaves them as they are.

On the product pageWhere it comes from
BrandThe store's brand or vendor field
ManufacturerOnly when the store names a maker separately from the brand
Product typeThe store's product type or categories
Material, ColourThe store's Material / Fabric and Colour options, every value it lists
Store tagsThe store's own tags, comma-separated
SKU, Barcode, WeightThe first size's codes and weight. The SKU also fills the product's SKU when that is empty
Was price, CurrencyThe crossed-out "was" price of the size that sets the price, and the store's currency (shown only when it is not rupees)

In a tag template (Websites → Tags) write {attr:brand}, {attr:manufacturer}, {attr:product_type}, {attr:sku} or {attr:barcode} for one tag, and {attr:store_tags} for one tag per store tag.

A detail the store does not show is simply left out — nothing is guessed. Open page at the top of the product page opens it on the other store. To tag every imported product with its brand, add the template Brand_{attr:brand} under Websites → Tags; a product without a brand just gets no brand tag.

The price

With Sell at their price on, the price shown on the other store becomes our selling price on every website — the lowest price of the sizes that are in stock. The websites' pricing rules (markup, rounding, minimum) are skipped for these products, and the product's Facts say "Sells at ₹… on every website (price copied from …)". A cost price is optional for them — they become Ready without one. Switch it off and no price is copied: each product waits in Needs info until you type a cost price, and the websites' pricing rules apply as usual.

Prices in another currency are never copied (a $29 dress must not become ₹29): the sheet then says Their price is not copied, and each product waits in Needs info. The same happens when a store does not say which currency it uses.

While it runs

  • The tile on Products shows what it found so far: found · added · already here · out of stock · failed. It refreshes by itself.
  • Cancel import stops it between pages; products already added stay.
  • Running the same store again skips every product that is already here (typed with or without "www"), so it is safe to repeat — for example to pick up new arrivals. It does not change the price or stock of the products it skips.
  • An import stops by itself after 5,000 new products (products already here do not count, so running it again picks up the rest), and after three pages in a row fail — the tile then says why, with Try again.
  • It goes at the pace of the AI: while many products are still waiting to be read or listings to be written, the import pauses, so a big store takes a day or more. If the store asks Playbook to slow down, it also waits a few minutes by itself.
  • When it is done, Show these products lists everything it added (filtered by the vendor).
  • Settings → Imports from websites lists the last 20 imports.
Tip Sites that ask automated visitors to stay away (a robots.txt rule) are refused with a plain message. Playbook never works around that.
Note Photos and text on another store are that store's copyright. Playbook writes new titles and descriptions with the AI for each of your websites, but the photos are copied as they are. Use this only on stores whose content you are allowed to reuse (your own other stores, a brand that supplies you, a store with written permission), or replace the photos before publishing.

12Tags: your own lists

You build the tags by hand, once, on Settings → Tags: each category uses some attributes (Colour, Work, Fabric…), and each attribute has its values (Black, Yellow, White…). Playbook only ever picks from your lists — it never invents a tag — so the tags stay tidy however many products arrive.

1 · Create attributes and values

  1. Open Settings → Categories & tags. Tap New attribute, name it (e.g. Colour) and choose Several (a product can be Pink and Wine) or One only (one Fabric).
  2. Under the attribute, type a value in Add a value and tap Add — Black, Yellow, White. Add Work (Embroidery, Printed, Sequins) and Fabric (Organza, Chiffon, Silk) the same way.
  3. Tap a value to rename it, add the words it is also known as (kala, kaala for Black), merge it into another value, or delete it. The number on each value is how many products carry it.

2 · Link attributes to categories

Under Categories, tap a category (this is the same list the AI picks a category from — it used to sit on Settings) and add the attributes it uses, in the order you like. Every attribute of a category is a must: a product without a value for one of them waits in Needs info and is not sent to websites.

Before linking, Playbook counts the products that lack it — "12 products will need a Colour" — and offers Link and let AI decide (links it and asks the AI to choose a Colour for those 12), Link only or Cancel. Unlinking frees them again.

3 · How products get their tags

StepWhat happens

5 · On a product

What you choose is kept — the text rules and the AI never change it again. Choosing the last missing value makes the product Ready and sends it to its websites.

6 · On websites

A website's Tags section sends the values with {tags}: Plain (Black) or Prefixed (Colour_Black, using each attribute's Shopify prefix). New websites start with {tags} in their templates; At most, per product caps the list.

Tip After adding values or "also known as" words, tap Retag all products on the Tags page: it first says how many products would change and how many would move between Ready and Needs info, then asks.

15Working with listings

Open a product, then tap a website in its Websites box. The listing opens with its price, title, description, SEO, handle and tags, and the buttons below.

Fixing a failed listing

  1. On the Dashboard tap Failed to publish (or filter Products by Listing: Failed).
  2. Open the product, then the website shown with the red text.
  3. Read the red text and fix the cause — see Troubleshooting.
  4. Tap Publish now (or Update on Shopify if it is already there).

The app also tries again by itself — up to 3 times, 10 minutes apart — so a short Shopify hiccup clears on its own.

Editing, and "kept" fields

Change any of Price (₹), Title, Description, SEO title, SEO description, Handle (URL) and Tags (comma list), then tap Save changes. Each field you change gets a small kept label: Regenerate will never touch it. Product Facts work the same way — a box you typed is kept and the AI reader never overwrites it.

Tip To hand a field back to the AI: empty the box, tap Save changes, then Regenerate. The kept label goes, and from then on the AI (and, for the price, the cost and the website's pricing) decides that field again. This works for price, title, description and both SEO fields.
  • On a published listing, after Save changes tap Update on Shopify to send the change.
  • While a listing is being written or sent to Shopify, editing is off. Close it and open it again in a minute.
  • Once a product is on Shopify its web address (handle) never changes, so old links keep working.

18Questions people ask

Does the app ever delete a product from Shopify?

No. Remove from site only sets it to Draft. Archive does not touch Shopify at all.

I changed a website's pricing / tags / writing. Are old products updated?

Not by themselves. New listings use the new settings. For a new price on a product already on Shopify, open the product and tap Check websites again — the price is updated on Shopify and the text stays. For new tags or writing, open the listing and tap Regenerate (and Update on Shopify if it does not go by itself).

Can one product have a different price on each website?

Yes. Every website has its own formula, and a rule can give a group of products its own markup.

The vendor's post shows a retail price, not our cost. What then?

The app always treats the number as your cost. Type your real cost in Cost price (₹) — what you type is kept.

Will the AI make things up?

It is told to use only the facts given and never to invent a fabric or size. Read the first listings of each website; anything you correct is kept.

What does the AI cost?

One AI call reads each product, and one call writes each listing on each website. Haiku is the cheapest; use Sonnet or Opus only where the writing really matters.

Are prices with or without GST?

The app sends the number from your formula. Whether Shopify treats prices as including tax is set in Shopify (Settings → Taxes and duties).

Who can see the Shopify keys?

Nobody. They are stored on the server, used only to talk to Shopify, and never shown again in the app.

What happens when I pause automation?

Nothing runs on its own until you switch it back on; buttons on a product still work. When it is switched on again it carries on from where it stopped.

Two of us edited the same listing. Whose change stays?

The last one saved. Close and reopen a listing before editing if someone else may have just changed it.
